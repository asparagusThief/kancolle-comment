# 检索评估与创作检查

这里保存 18 个构造的典型玩家请求，用于检查案例检索能否支持角色日常、季节问候、玩家感想、游戏体验和两栏组合。它们不是收集到的真实玩家反馈，也不是官方选拔标准。评估材料供维护使用，不放进安装版 Skill 的提示或数据包。

## 数据与方法

- `requests.json` 固定中文请求、检索词和重点词；9 个用于开发，9 个留作保留集。v1.5.0 基线不支持 `--prefer`，新版本使用请求中预先给出的重点词。这次对比同时包含新增重点表达能力与排序调整的效果。
- `relevance.json` 是排序改动前冻结的 220 条初始判断；候选池包含旧版前 8 条，以及按重点词匹配补充的候选。初始判断在比较中保持不变。
- `supplemental-relevance.json` 为排序规则固定后，新版及关闭多样性版本进入前 8 条的 66 条新增候选补充判断。所有对照使用同一套合并判断，没有把未评阅记录默认为已确认无关。
- 评分为 2（直接有助于本次对象和情境）、1（可借鉴的局部构思或其他角色的类似场景）、0（无关、仅顺带命中字串或与情境冲突）。`idea` 是编辑归纳的构思类别。
- 全部判断由同一维护智能体进行，未做独立玩家评审或盲测。文字按现有核实文本或 OCR 阅读，相关性判断不核实原文、角色设定和引用来源。

排序开发只使用开发集；查看新版保留集结果后没有再调整排序权重。随后优化了相似度缓存，并核对 18 个请求的展示 ID 与冻结版本完全一致。所有结果均使用种子 42、最多 8 条。

`useful_at8` 是前 8 条中评为 1 或 2 的比例；`direct_at8` 是评为 2 的比例。NDCG 的理想排序仅来自已评阅候选池，不表示全库召回率。`distinct_useful_ideas_at8` 为有参考价值结果中的不同构思类别数；标签归纳具有主观性。未评阅结果计零只是计算下界，必须同时查看判断覆盖率；本次保存的各版本前 8 条覆盖率均为 100%。

## v1.6.0 对照结果

| 指标 | v1.5.0 基线 | v1.6.0 |
| --- | ---: | ---: |
| 全部请求：可借鉴比例 | 77.78% | 89.58% |
| 全部请求：直接相关比例 | 31.25% | 42.36% |
| 全部请求：平均不同构思数 | 4.94 | 5.44 |
| 保留集：可借鉴比例 | 73.61% | 88.89% |
| 保留集：直接相关比例 | 31.94% | 48.61% |
| 保留集：池内 NDCG@8 | 0.5826 | 0.8353 |

这是一组小规模、单一评阅者的检索结果，不证明日语生成质量或入选机会提升。逐请求结果保存在 [基线报告](reports/baseline.json)、[新版报告](reports/v1.6.0.json) 和 [关闭措辞多样性的报告](reports/without-diversity.json)。报告带脚本、数据和判断文件哈希。

措辞多样性有取舍：关闭它时，全体可借鉴比例为 90.97%，平均构思数为 5.28；启用时分别为 89.58% 和 5.44。它减少重复字串，但不识别同义构思，故保留 `--no-diversity` 供需要时使用。

仍需改进的具体情况：

- 加贺喝茶、朝潮旅行两个开发请求的可借鉴比例分别从 87.5%、100% 降为 75%、75%；角色名匹配仍可能带入不同目的的文本。
- 单字“電”、天气与角色同形字、仅舰队名中出现的主题仍需编辑判断；脚本没有日语词义消歧或角色事实识别。
- 节气、活动、台词背景及具体性格需要另行核查，检索分值不能代替这些工作。

## 创作检查

[creative-smoke.json](creative-smoke.json) 保存 6 个请求下的 18 条原创候选，包含日文、中文意思、构思说明和脚本检查结果。检查项目为请求契合度、玩家口吻、日语自然度、同批构思差异、两栏配合，以及是否把原创场景声称为官方事实。

18 条均通过各栏 12 字限制，未与库内历史 comment 同文；自然度与构思由同一维护智能体作编辑自检。没有做旧版和新版的独立生成对照，也没有对这些纯玩家表达进行角色设定研究；不能据此声称已验证所有角色均不 OOC。

## 复现

在仓库根目录运行，Python 3.9+，只使用标准库：

```text
python evals/run.py --output /absolute/path/result.json
python evals/run.py --split holdout
python evals/run.py --no-diversity
python evals/test_search.py
```

保留 v1.5.0 的 `scripts/corpus.py` 后，可用 `python evals/run.py --script /absolute/path/old-corpus.py` 重跑基线；对应 Git 提交为 `0ba404482587ce1f00e9ce41be7d30b4cbc7bd70`。`--skill-dir` 可指定另一个完整 Skill 目录。运行器检查 CSV 哈希和核实案例 JSON 的规范化内容哈希，避免跨平台换行差异造成误报；数据更新后，应先复核评阅依据再更新基准，不能把数据变化当作排序效果。
