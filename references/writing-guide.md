# 创作与编辑

## 选择表达方向

以当前请求决定风格。角色喜爱、幽默、日常记录、季节问候、抒情、游戏体验和目标宣言都可以成立；历史入选不等同于必须有笑点。

案例可从四个方面理解：

- **主题**：句子在表达什么，是否与玩家的要求相关。
- **表达方法**：直抒感想、具体细节、反差、夸张、谐音或游戏用语借用等。
- **两栏关系**：舰队名与 comment 各自独立、呼应，或构成铺垫与收尾。
- **背景依赖**：理解它需要哪些角色、活动、季节或语言知识。

这些是文本分析维度，不是官方选拔标准。只凭入选记录无法确认获选原因；出现次数也不应作为套用模板的理由。

## 使用案例

按主题和表达目的检索，不让某一批精选样本决定所有输出的题材。`curated-examples.json` 含 1000 条已核实舰队名与 comment 的记录，以及中文解读和来源；覆盖 2018—2026 年、全年 12 个月份和 20 个服务器。先用 [主题索引](curated-index.md) 或主题筛选选择相关内容，不必整份载入；这些案例仍不是完整库题材分布的随机样本。

参考其写法后重新构思，避免只更换角色名、季节词或名词。历史 comment 里的角色互动可能是愿望、同人场景或玩笑；其中的旗舰不能证明句子是该角色的官方设定。

## 角色关联

具体核查方法见 [角色资料核查](character-research.md)。以玩家视角写感想、陪伴、同行愿望或具体小事，是角色相关文案的主要方向。角色选择可以决定与谁相处，不必决定整句采用哪条原台词。

先判断是谁在说话。普通签名保持玩家的口吻；用户要求角色独白或对话时，再使用角色的自称、称呼与语尾。角色资料用于核对设定和避免明显冲突，平常的相处场景可以原创。

台词引用、改词和口癖梗是可选的表达方法。未要求玩梗时，让候选主要凭文字、情境和感受独立成立；检索后不围着同一句原台词连续换词。也不把一切角色关联都简化成一个代表性物品、天气或动作。

按需检索 `--theme "玩家感想"`、`--theme "相处场景"` 或 `--theme "游戏日常"`，从多种角色和生活主题中观察构思方法，再为当前请求新写。主题标签说明阅读角度，不能据此断言历史作者从未引用台词；具体引用来源仍需另外核查。

可观察这些实际入选文本的构思：`230101-04` 写与朝潮旅行，`231204-04` 写为山风拿出被炉，`250410-02` 向电道谢，`260517-08` 在舰队名表达角色偏好、comment 则谈演习。它们按字面就能成立，说明角色关联可以通过场景、玩家感情或两栏组合表达。借鉴这种构思空间，重新写本次用户的内容。

对温柔、强势、害羞等性格概括，回到具体台词及场合判断。不要把单一标签扩展为任何情境下的固定反应。若玩家明确指定同人设定或反差改写，将其作为本次创作前提，并与游戏资料区分。

## 编辑判断

检查正文能否独立理解、是否符合目标口吻、双关是否在日语中成立、释义是否对应原文，以及两栏的配合是否有意义。长度不足以容纳内容时换一种表达，不靠生硬删词维持原方案。

同一批候选应有实质区别；后续修改承接玩家的反馈。推荐时说明文字本身的优点，不把个人审美包装成评选规律。
